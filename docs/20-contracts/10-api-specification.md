# 10 — API specification

**Status:** Draft
**Owner:** Founding team
**Last updated:** 2026-10-15

This document is the wire contract for the three surfaces through which anything talks to Steward: the public REST API served by the control plane (agents through the SDK, humans through the UI, CI through generated clients), the control-plane ↔ data-plane gRPC session that carries heartbeats, changeset reports, and instructions across the trust boundary, and the data-plane-local gRPC between proxy, engine, and adapter host (summarised only; docs 04, 05, 08, 09 define them). It fixes conventions, the auth and capability model, every REST resource with the doc 13 transition it triggers, the full protobuf for the cross-plane session, webhooks, and three end-to-end transcripts. Every file described here lives in `contracts/` (doc 18 §1).

## 1. Surfaces and file layout

| Surface | Transport | Clients | Defined in |
|---|---|---|---|
| (a) Public API | REST over HTTPS, JSON, base path `/v1` | SDK and MCP server (doc 11), LiveView UI (same endpoints), CI | `contracts/openapi/steward.v1.yaml` |
| (b) Control ↔ data plane | gRPC over mTLS, one bidirectional stream per data plane | `steward-engine` (doc 05) as client; control plane gRPC host (doc 07, port 50051) as server | `contracts/proto/steward/plane/v1/session.proto` |
| (c) Data-plane local | gRPC over Unix domain sockets | proxy ↔ engine, proxy/engine ↔ adapter host | `contracts/proto/steward/engine/v1/*.proto`, `contracts/proto/steward/adapter/v1/adapter.proto` |

Surface (c) services, named here for completeness and **not** re-specified: `steward.engine.v1.Engine` (`ComputeChangeset`, `GetRowDelta`, `StalenessCheck`, `ComputeCompensation`, `Compact`, `CloseOverlay`; doc 05 §3.1), `steward.engine.v1.CompensationLog` (`Persist`, `Open`, `Release`, `Keys`, `Status`, `List`, `Verify`, `VerifyChain`, `SetRetention`, `SetLegalHold`, `Export`; doc 09 §3.1), `steward.engine.v1.ProxyFacts` (New: the proxy's per-branch facts report to the engine, doc 04 §5.6, previously unnamed), and `steward.adapter.v1.Adapter` (a one-to-one mirror of the Java `Connector`; doc 08 §3.1). Generated code is checked in per language under `contracts/gen/{rust,elixir,java,python,typescript}/`.

## 2. Conventions

| Convention | Rule |
|---|---|
| Base path | `/v1`. Hosts: `api.<region>.steward.dev` for the control plane; the data-plane grant endpoint is at the customer's data-plane hostname (§3.3). |
| Encoding | JSON, UTF-8, `snake_case` keys. Unknown request keys are rejected with `invalid_request` (doc 07 §8: embedded schemas reject unknown keys). |
| Timestamps | RFC 3339 with `Z`, microsecond precision. |
| Identifiers | UUIDv7 (RFC 9562), lower-case text. **Decision:** v7 over v4 because branch, changeset, event, and merge rows are inserted in time order and read by recency; v7 gives B-tree locality in metadata Postgres and keyset pagination for free. The embedded timestamp leaks nothing the resource does not already expose as `created_at`. Branch ids remain legal Postgres database names (doc 04 §3.1). Overlay ids are generated by the data plane and are also v7. |
| Pagination | Cursor: `?limit=` (default 50, max 200) and `?cursor=`; responses carry `next_cursor` (opaque, null at end). Keyset on `(created_at, id)` or as the resource states. |
| Idempotency | Every mutating `POST` **must** carry `Idempotency-Key: <string ≤ 128 chars>`; missing → `400 invalid_request`. Stored as `(principal, key) → result` for 24 h (doc 13 §8). Replay returns the stored status and body plus `Idempotent-Replayed: true`. Same key, different payload → `409 idempotency_conflict`. `PATCH` and `DELETE` are idempotent by definition and take no key. |
| Controller shape | Every endpoint maps to exactly one Ash action in a `Steward.Core` domain (doc 07 §5.0); the Phoenix controller decodes the request, passes `actor:` and `tenant:`, calls the action, and renders, and **must not** contain business logic or capability checks. The REST shape here is hand-owned and is not generated from the resources (AshJsonApi rejected, doc 07 §11). |
| Error envelope | `{"error": {"code": string, "message": string, "details": object, "request_id": string}}`. `message` never contains row values, SQL text with literals, or secrets. One `FallbackController` maps `Ash.Error` classes to §2.1: `Ash.Error.Invalid` → `400 invalid_request` (or the named `409`/`422` code when the action's error carries it), `Ash.Error.Forbidden` → `403 forbidden`, `Ash.Error.Query.NotFound` and cross-tenant misses → `404 not_found`, `Ash.Error.Unknown` → `503 unavailable`. |
| Request id | `X-Request-Id` echoed or generated; it is the trace id propagated to data-plane calls (doc 07 §9). |
| Rate limits | New: per API key, token bucket, default 600 requests/min and 60 mutating/min; per org 6,000/min. Headers `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset` (seconds) on every response; over budget → `429 rate_limited` with `Retry-After`. |
| Versioning | Within `/v1`: additive only (new optional fields, new endpoints, new enum values only where the field is documented as open). Removing or changing the meaning of a field requires `/v2`. Deprecation: a `Deprecation` header and 12 months' notice before removal; `/v1` is supported for 12 months after `/v2` ships. Protobuf: fields never renumbered or reused; `reserved` on removal. |
| Capability check | Performed before idempotency lookup; `403 forbidden` is never cached. |

### 2.1 Error code enum

Stable, closed set. Lifecycle reasons and adapter codes are reused verbatim where they surface.

| HTTP | `code` | Source | When |
|---|---|---|---|
| 400 | `invalid_request` | New | Schema violation, missing `Idempotency-Key`, bad cursor |
| 401 | `unauthenticated` | New | Missing, unknown, or revoked key/token |
| 403 | `forbidden` | doc 06 §6 | Capability missing; self-approval → `self_approval` (doc 07 §5.5) |
| 404 | `not_found` | New | Resource absent or outside the caller's org (never distinguishes the two) |
| 409 | `idempotency_conflict` | doc 13 §8 | Key reused with a different payload |
| 409 | `stale_transition` | doc 07 §5 | Branch not in the required state (e.g. propose on a non-`open` branch) |
| 409 | `changeset_superseded` | doc 13 §6.4 | Review on a changeset that is no longer current |
| 409 | `already_reviewed` | doc 13 §6.4 | Concurrent reviewer won |
| 409 | `merge_in_progress` | doc 13 §6.7 | Abandon on a `merging` branch |
| 409 | `verdict_block` | doc 07 §5.5 | Approve on a `block` verdict |
| 409 | `compensation_unavailable` | New (wraps doc 09 §5.3 refusals) | Revert refused; `details.reason` ∈ `consumed`, `expired`, `corrupt`, `reserved_by` |
| 409 | `policy_activation_refused` | New (wraps doc 06 §5.2 preconditions) | `details.reason` ∈ `not_draft`, `tests_failing`, `no_tests`, `static_check_failed` |
| 422 | `policy_invalid` | New | Static check failed; `details.errors[].code` ∈ `unknown_relation`, `unknown_column`, `bad_shape` (doc 06) plus parse errors |
| 429 | `rate_limited` | New | §2 |
| 501 | `review_edit_not_supported` | New | `decision: edited` in M0 (doc 13 §12) |
| 503 | `unavailable` | doc 06 §6 | Metadata Postgres unreachable |
| 503 | `data_plane_unreachable` | doc 13 §6.5 | Create/propose/revert failed before checkpoint because the data plane did not answer |

Response bodies that describe a terminal branch carry `reason` from the lifecycle set: `snapshot_lost`, `ttl_expired`, `compute_failed`, `stale_base`, `compensation_failed`, `data_plane_unreachable` (doc 13), `review_rejected`, `verdict_block`, `abandoned_by_principal`, `merge_applied`, `retention_elapsed` (the canonical list is doc 12 §3 `lifecycle_reason`). Verdict `reason` is doc 06's: `policies`, `policy_error`, `no_policy_coverage`, `revert_conflict`.

## 3. Auth and principals

Principals are first-class (doc 02) with `kind ∈ agent | human | service` (doc 06 §4.1).

### 3.1 Agent and service credentials: API keys

Format `stw_<prefix>_<secret>` (doc 07 §8; human short-lived tokens use `stwt_`). Stored as SHA-256 of the secret, prefix indexed. A key belongs to one principal, one org, and a set of targets, and carries capabilities:

| Capability | Grants |
|---|---|
| `branch:write` | Create, withdraw, abandon branches on the key's targets; connect through the proxy (the same key is the pgwire password, doc 04 §3.1) |
| `branch:propose` | Propose |
| `changeset:read` | Get changesets, verdicts, fired assertions |
| `review:read` | List the queue |
| `review:decide` | Approve / reject (humans only in M0; a key for an agent **must not** carry it) |
| `policy:read`, `policy:write`, `policy:admin` | doc 06 §8 `policy_read` / `policy_write` / `policy_admin`. Agents **must not** hold `policy:write` or `policy:admin` in M0 (doc 06 §8) |
| `target:admin` | doc 07 `target_admin`: settings, memberships, retention, revert, impact queries |
| `merge:revert` | Initiate a revert (`POST /v1/merges/{id}/revert`); for service principals, implied by `target:admin`; agent keys **must not** carry it in M0 (doc 13 §6.6) |
| `audit:read` | List audit events |
| `webhook:admin` | Register webhooks |

Header: `Authorization: Bearer stw_...`. The `resource:verb` spelling is New; doc 07's human membership capabilities map onto it: `reviewer` = `review:read` + `review:decide` + `changeset:read`; `policy_admin` = `policy:*`; `target_admin` = `target:admin` + everything above. `org_admin` (on the principal) grants principal and key management.

### 3.2 Humans

SSO (OIDC, doc 07 §8) establishes a Phoenix session; the LiveView UI calls the same contexts the REST controllers call. For API use a human exchanges the session for a token: `POST /v1/auth/tokens` → `{token: "stwt_...", expires_at}` (New; 1 h, not renewable, carries the human's memberships).

### 3.3 Row-delta grant

`POST /v1/changesets/{changeset_id}/grants` (doc 07 §5.6). Requires `review:read` on the target. Returns:

```ts
{ grant: string /* ES256 JWT */, data_plane_url: string, expires_at: string }
```

Claims exactly as doc 07 §5.6: `iss`, `aud` (data-plane id), `sub` (principal id), `org`, `cs` (changeset id), `scope` ∈ `row_delta:read` | `compensation:read` | `compensation:export:<target_id>` (doc 09 §5.6), `jti`, `exp` = iat + 5 min. The data plane serves `GET {data_plane_url}/v1/changesets/{cs}/row-delta?table=&cursor=`, `.../assertions/{policy_id}/{assertion_id}/samples` (resolves `sample_ref`, doc 05 §5.4), and `.../compensation/{merge_id}` with `Authorization: Bearer <grant>`; the control plane never sees the response. Every issuance is a `grant.issued` event; every use is a data-plane audit event (doc 09 §8).

### 3.4 Data planes

mTLS client certificates issued at enrolment (doc 14); the certificate SAN is the data-plane identity used for the heartbeat token bucket and as the grant `aud` (doc 07 §8).

## 5. Control ↔ data plane: `steward.plane.v1.Session`

**Decision: one bidirectional stream, opened by the data plane.** The control plane never needs inbound network access to the customer's cloud; the customer's egress rule is one hostname on 443. Docs 04, 05, and 07 name the control-plane-originated calls (`InitialiseOverlay`, `FreezeWrites`, `ComputeChangeset`, `Merge`, `CloseOverlay`, `RoutingUpsert`); those are `Instruction` messages on the stream with a correlation id, and the data plane answers with `InstructionResult` on the same stream, so the timeouts of doc 07 §3.2 (freeze 2 s, overlay init 10 s, others 5 s; compute deadline 15 min) are enforced by the control plane as reply deadlines, not transport timeouts. If the stream is down the instruction is queued per the retry budgets in doc 13 §6 and re-sent on reconnect; the heartbeat matrix repairs the rest. A data plane **must** keep exactly one stream open per data-plane identity and reconnect with jittered backoff (1 s → 60 s).

```protobuf
syntax = "proto3";
package steward.plane.v1;
import "google/protobuf/timestamp.proto";

service Session {
  // Data plane opens it. mTLS; the client certificate SAN is the data-plane id.
  rpc Connect(stream DataPlaneMessage) returns (stream ControlPlaneMessage);
}

// New (doc 14 §6): one unary call over plain TLS (no client cert) that exchanges the enrolment token for the identity cert.
service Enrolment {
  rpc Enrol(EnrolRequest) returns (EnrolResponse);
}
```

**Boundary enforcement.** No message above has a field that can carry a row: summaries are typed aggregates, impact is `name → number`, evidence is counts, digests, and paths, assertion results are status plus count plus `sample_ref` (doc 07 §8). Additionally the server sets `grpc.max_receive_message_length = 1 MiB` for every `DataPlaneMessage` and the client the same for `ControlPlaneMessage` except `ComputeChangeset`, which may carry up to 4 MiB of SQL bodies (doc 06 §7 estimates < 1 MB); the engine truncates a summary to 256 KiB before sending (doc 05 §5.2). A message over the limit is rejected with `RESOURCE_EXHAUSTED` and counted in `steward_plane_oversize_total`; it is never partially accepted. Heartbeat storms: `RESOURCE_EXHAUSTED` with `retry_after_ms` in status details (doc 07 §5.3).

## 6. Webhooks

Payload per delivery, one event per request:

```ts
{ id: string /* event id */, type: string, org_id: string, aggregate_type: string, aggregate_id: string,
  occurred_at: string, payload: object /* same as /v1/audit-events */, api_version: "v1" }
```

Event types (canonical list and payloads: doc 12 §6.1; doc 07 §5.7 names those marked †; the rest are the per-transition events doc 07 §5 requires and are New as names): `branch.created`, `branch.proposed`, `branch.withdrawn`, `branch.merging`, `branch.merged`, `branch.rejected`, `branch.abandoned`, `branch.closed`, `branch.returned_to_open`, `branch.heartbeat_lost`†, `changeset.computing`, `changeset.evaluated`†, `changeset.superseded`, `review.recorded`, `merge.started`, `merge.checkpointed`, `merge.applied`, `merge.failed`, `merge.stalled`, `merge.compensated`, `target.lease_expired`†, `target.lease_released`, `target.health_changed` (New, doc 16), `heartbeat.anomaly`†, `grant.issued`†, `policy.version_saved`, `policy.activated`, `policy.retired`.

Headers: `Steward-Event-Id`, `Steward-Event-Type`, `Steward-Signature: t=<unix>,v1=<hex HMAC-SHA256(secret, t + "." + body)>`, `Steward-Delivery-Attempt`. Delivery is at-least-once, ordered per aggregate on a best-effort basis; receivers dedupe on `id`. Retry on non-2xx or 5 s timeout: 1 min, 5 min, 30 min, 2 h, 12 h, 24 h, then the webhook is `suspended` and a `webhook.suspended` event is recorded. Delivery is an Oban consumer of `events` (doc 07 §5.7), so it is atomic with the state change that produced it.

## 8. Compatibility and SDK generation

`contracts/openapi/steward.v1.yaml` is the single source for generated clients in `sdk/python`, `sdk/typescript`, and the MCP server (doc 11); hand-written code in the SDK is limited to retry policy (`SD002` for 60 s; 503 with backoff), idempotency-key generation, and connection-string handling. Protobuf under `contracts/proto/` generates the Rust (`tonic`/`prost`), Elixir (`elixir-grpc`/`protobuf`, doc 07 §3.1), and Java (`grpc-java`) stubs checked into `contracts/gen/`. CI diffs generated output against the committed copy and fails on drift; a change to `contracts/` is a public contract change (doc 18 §5). OpenAPI examples are the transcripts in §7 and are executed as contract tests under `tools/e2e`.

## 9. Alternatives considered

- **GraphQL for the public API.** Flexible reads for the UI. Rejected: the UI is LiveView and calls contexts directly; agents need six endpoints; idempotency and capability semantics per mutation are clearer as REST; generated clients from OpenAPI are mature in both SDK languages.
- **gRPC for the public API too.** One toolchain. Rejected: agents reach Steward through SDKs and an MCP server, and HTTP/JSON keeps `curl` and CI scripts trivial; gRPC-Web would add a proxy. gRPC is kept for the plane boundary, where streaming and typed messages enforce invariant 9.
- **Control-plane-initiated unary RPCs into the data plane** (as docs 04/05/07 read literally). Simpler mental model. Rejected: requires inbound access to the customer's cloud or a gateway (doc 05 §3.1 mentions one); the data-plane-opened stream needs one egress rule and no gateway, and every instruction is already retried through the heartbeat matrix.
- **Long-polling instead of webhooks.** No receiver endpoint to secure. Rejected as the only mechanism: `GET` on branches and changesets is polling and remains available; webhooks exist for CI and chat integrations that cannot poll cheaply.
- **UUIDv4.** No timestamp leakage, universal library support. Rejected for index locality and keyset pagination; v7 support is in every target language's standard or de-facto library.
